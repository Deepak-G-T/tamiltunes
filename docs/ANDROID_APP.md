# TamilTunes as an app (PWA now, Android APK next)

Distribution: **direct APK and the installable web app only.** No Play Store listing: the music source (JioSaavn) is unlicensed, and Google Play requires proof
of licence. Keep it that way unless the catalogue becomes licensed.

## Phase 1: installable web app (PWA) - done
- **Icons** come from the login-page logo (green gradient square `#17a34a` -> `#1ed760`, white lucide "eighth-note"), generated by
  `node scripts/make-icons.mjs` into `frontend/public/icons/` (192, 512, maskable 192/512, apple-touch 180, splash source 2732) on `#09090B`;
  `favicon.svg` is the same logo. Screenshots for the install dialog: `node scripts/make-screenshots.mjs` (placeholder covers; replace with real ones any time).
- **Manifest + service worker** are built by `vite-plugin-pwa` (`injectManifest`, worker in `src/sw.js`, rules in `src/lib/swRules.js`).
  Cached: the app shell (precache), pictures (stale-while-revalidate), and ONLY the public music endpoints `/api/music/home|search|albums/:id|artists/:id`.
  NEVER cached, and not even intercepted (no route at all, so the browser handles them natively and Range requests keep working): audio/video streams (any Range request, `/stream`, saavncdn / googlevideo / youtube hosts), sign-in and every personal endpoint
  (auth, me, admin, home, history, favorites, playlists, comments, profile, queue). Offline page loads show `/offline.html`.
  A new version waits for the "Reload" bar (a silent reload would stop the music).
- **Install**: the browser's install offer is captured at startup (`lib/pwa.js`), shown as a dismissible bar (remembered 30 days) and on the page `/install`
  (Android APK link + install steps for Android, iPhone, computer). The APK link is `src/config/app.js` (`VITE_APK_URL` overrides it).
- **Mobile**: viewport allows zoom, `100dvh` + safe areas on `#root`, `--nav-h` bottom bar with the real gesture-bar inset (the old `pb-safe` class did not exist),
  no browser pull-to-refresh (the home page has its own), 44px mini-player controls.
- **Media Session**: handlers (play, pause, stop, previous, next, seek) registered once and read the latest functions from a ref; metadata is built once per song
  with 6 artwork sizes (app icon when a song has no cover); position state for the lock-screen seek bar.
- **YouTube songs** pause when the screen locks (YouTube's player and rules): the full-screen player says "This song pauses when the screen locks."
- Browser checks: `npm run test:pwa --prefix frontend` (needs port 5000 free; it runs a tiny mock API), plus the queue / ui / home / search audits.

### Lighthouse (mobile, Lighthouse 11.7.1, simulated slow 4G + 4x CPU, the built app on a local preview with a mock API)
PWA 100 (installable manifest, maskable icon, splash, themed address bar) - Accessibility 100 - Best practices 96 - SEO 97 - Performance 83-86 (3 runs;
FCP 1.9 s, LCP 3.8 s, TBT 130-220 ms, CLS 0). Performance is below 90: the cost is main-thread JavaScript under the throttle, not the network.
Left alone: the tap-target note (the "..." button sits on the whole-tile button of a Speed Dial tile) and a console error for `youtube.com/iframe_api`
(unreachable from the test sandbox; fine on the real network). Measure the real deployment with PageSpeed Insights.

Chrome on Android, installed from the browser (menu > Install app, or the bar on the home page / the `/install` page):
1. Install works and TamilTunes opens full screen with the green icon and a dark splash. [UNTESTED]
2. Play a song (not a YouTube one), lock the screen: music keeps playing. [UNTESTED]
3. Lock-screen / notification shows the title, artist and cover, and play/pause/next/previous/seek bar work. [UNTESTED]
4. Receive a call (or start another audio app): the song pauses, and resumes afterwards. [UNTESTED]
5. Turn airplane mode on and reopen the app: you see the offline page, not a blank screen. [UNTESTED]
6. Rotate the phone with the player open, then the queue: nothing breaks. [UNTESTED]
7. Press Back with the queue / player open: it closes first (this is the installed app's behaviour; the APK handles Back natively in Phase 2). [UNTESTED]
8. Play a YouTube-sourced song, lock the screen: it pauses and the player showed the notice. [UNTESTED]
9. Log in, close the app, reopen: still logged in and the queue is back. [UNTESTED]
